## 2026-10-19 — M04 — 404 for a hidden person through `src/proxy.ts`

**Question:** M04 In scope 4 says a hidden person returns 404, and In scope 6 asks for a deliberate 404. With Cache Components and Partial Prefetching, a person page streams its shell with status 200 before it knows whether the person exists, so the page itself cannot answer 404. The version-matched Next.js docs give a request-time check in Proxy as the supported way, and CLAUDE.md §13 allows a `proxy.ts` whose matcher excludes `api`, `healthz` and `_next`, but its first sentence says "There is no `proxy.ts` in Phase 1". Which way should the person pages answer?

**Options:**
1. **A proxy for the two person paths only** (implemented): `src/proxy.ts` with `matcher: ['/people/:slug', '/people/:slug/lineage']` asks the lineage service whether this viewer may see the person and otherwise rewrites to the app's not-found page, which answers 404 with "Not on the record" in the HTML (also without JavaScript). Hidden, missing and malformed addresses get the same status and HTML. One indexed database read per person page request; the session is read only for an address that is not public. Details: `docs/adr/0008-person-pages-404.md`.
2. **No proxy:** the pages answer 200 with `noindex, nofollow` and the same "Not on the record" body for hidden and missing people (the first M04 version); only the API answers 404.

**Proposed default:** option 1. If you keep it, please update the first sentence of CLAUDE.md §13, for example to: "`src/proxy.ts` runs only for `/people/:slug` and `/people/:slug/lineage` (the 404 of a hidden person, M04, ADR 0008); its matcher never includes `api`, `healthz` or `_next` (plan §6.1)." Claude does not edit CLAUDE.md itself. `scripts/verify.d/M02.sh` now enforces that rule instead of "no proxy.ts": no `middleware.ts`, no root `proxy.ts`, and a `src/proxy.ts` matcher with person page paths only. If you choose option 2, `src/proxy.ts`, `src/proxy.test.ts` and `src/lib/not-on-record.ts` are removed, the M02 check goes back, and `e2e/routes.ts` expects 200 again.
