## 2026-10-19 — M04 — 404 for a hidden person through `src/proxy.ts`

**Question:** M04 In scope 4 says a hidden person returns 404, and In scope 6 asks for a deliberate 404. With Cache Components and Partial Prefetching, a person page streams its shell with status 200 before it knows whether the person exists, so the page itself cannot answer 404 (re-checked in review round 2: `notFound()` from the page, without a proxy, still answers 200). The version-matched Next.js docs give a request-time check in Proxy as the supported way. CLAUDE.md §13 says "There is no `proxy.ts` in Phase 1; if one is added, its matcher excludes `api`, `healthz` and `_next`", and the M02 check `no proxy.ts or middleware.ts in Phase 1 (CLAUDE.md §13)` enforces the first half. Which way should the person pages answer?

**Options:**
1. **A proxy for the two person paths only:** `src/proxy.ts` with `matcher: ['/people/:slug', '/people/:slug/lineage']` asks the lineage service whether this viewer may see the person and otherwise rewrites to the app's not-found page, which answers 404 with "Not on the record" in the HTML (also without JavaScript). Hidden, missing and malformed addresses get the same status and HTML. One indexed database read per person page request; the session is read only for an address that is not public. This needs a change to CLAUDE.md §13 and to the M02 check, which only the owner can make (CLAUDE.md §9). It was implemented in review round 1 (commit `e7aa459`) and removed again in round 2 (commit `348f9c3`), so `git revert 348f9c3` restores it.
2. **No proxy** (the shipped default since review round 2): the pages answer 200 with `noindex, nofollow` and the same "Not on the record" body for hidden, missing and malformed addresses, in the HTML itself (also without JavaScript); the API answers 404. CLAUDE.md and the M02 check stay as they are. Search engines see a "soft 404" that is never indexed. Details: `docs/adr/0008-person-pages-404.md`.

**Proposed default:** option 2, because it needs no change to a project rule or check. Option 1 is recommended if the HTTP status matters for the pilot. If you choose it, please update the first sentence of CLAUDE.md §13, for example to: "`src/proxy.ts` runs only for `/people/:slug` and `/people/:slug/lineage` (the 404 of a hidden person, M04, ADR 0008); its matcher never includes `api`, `healthz` or `_next` (plan §6.1)." Then `git revert 348f9c3` brings back `src/proxy.ts`, `src/proxy.test.ts`, `src/lib/not-on-record.ts`, the ESLint rule for the proxy, the M02 check that allows only that proxy, and the 404 in `e2e/routes.ts` and the E2E test. ADR 0008 and the guides are updated in the same PR.
