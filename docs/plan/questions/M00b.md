## 2026-10-17 — M00b — Colour of "Verified"

**Question:** the Ink Lineage prototype stamps verified links with a red seal; plan §5.2 makes `--verified` green (`#00E676`) and reserves red for the primary button. Which colour should "Verified" use?

**Options:**
1. Jade green: `#45D98F` in the dark theme, `#0A6E43` in the light theme. Red stays for the brand mark and the primary action only.
2. Red seal, as in the prototype: red then means both the brand and "verified".
3. The plan's `#00E676` (dark) with a darker green for the light theme.

All three pass the contrast checks in `src/design/contrast.test.ts`, and the state is always shown by stroke, seal and text as well, never by colour alone.

**The shape of the seal (added after the second review).** The first version, a square chop with a carved check, read as a ticked checkbox (☑), most of all at 13 px in the line and in the "Verified" badge. The default is now a round chop pressed slightly askew with a brush check carved out of it, the way an official seal is stamped: from 20 px it has a hand-cut edge and a carved ring broken where the check leaves it; below 20 px it is a simplified oval with a bolder check (`src/components/ink/seal.tsx`, `/styleguide`). The other states keep their outline shapes (square with an hourglass, dashed circle with "?", diamond with scales), so "verified" is the only filled seal.

**Proposed default:** option 1, jade green, on the round chop (recorded in `docs/adr/0006-design-system.md`).

## 2026-10-17 — M00b — Budgets and the theme without JavaScript

**Question:** plan §5.8 (c) says a budget threshold is not raised without the owner's decision once it is recorded. M00b set three defaults around the budgets and the theme that the owner has not confirmed yet. Do you accept them?

**(a) The `/styleguide` JavaScript budget.** The developer page shows every overlay component at once and loads 240.5 kB (gzip) against the 170 kB of a content route.

1. Keep 250 kB for this `noindex` developer page only (every other route stays at 170 kB).
2. Leave `/styleguide` out of production builds and out of the budget.
3. Split the overlay demos into their own pages so each fits 170 kB.

**(b) How Lighthouse slows the page down.** Lighthouse's simulated throttling (Lantern) estimates LCP 2.78 s on `/` from the local server, because its pessimistic graph counts async scripts that have finished long before the real paint. With applied throttling (`throttlingMethod: devtools`: slow 4G, 4× CPU, mobile profile) LCP is about 1.7–1.9 s and CLS 0. The 2.5 s threshold is unchanged.

1. Keep `devtools` throttling.
2. Go back to simulated throttling and make `/` fit 2.5 s under Lantern (smaller hero, fewer scripts before LCP).

**(c) The manual theme choice without JavaScript.** The server cannot read the theme cookie without making every route dynamic (Cache Components), so a small script in `<head>` applies the choice before the first paint. With JavaScript turned off the page follows the system theme and the theme switch does nothing. The Done-when test title still says "the server renders it without a flash"; the test checks `data-theme` and `theme-color` when `<body>` first appears.

1. Accept the head script (the page still never flashes when JavaScript runs).
2. Render the theme on the server and accept dynamic rendering for every route.

**Proposed default:** (a) option 1, (b) option 1, (c) option 1 (recorded in `docs/adr/0006-design-system.md`).
