## 2026-11-02 — M13 — How many Lighthouse runs decide a route of `pnpm perf:web`

**Question:** `lighthouserc.json` says three runs per route with the median deciding (`numberOfRuns: 3`, `median-run`). Three runs of each of the 32 main routes take about 33 minutes, too long for the CI job, so `pnpm perf:web` used to run a route once and rerun it only when it failed. How should a route be decided?

**Options:**
1. **A margin rule: a route's first run decides alone only when every budgeted metric (LCP, CLS) is within 90 % of its budget (LCP ≤ 2250 ms, CLS ≤ 0.09); otherwise the route runs twice more and the median of the three decides. The budgets are unchanged; the run logs which routes got three runs.**
2. The margin rule in CI, and the median of three for every route in a separate nightly job.
3. The median of three for every route everywhere, with a longer CI job (about 33 more minutes).

**Proposed default:** option 1, applied (`DEFAULT` at `CLEAR_MARGIN` in `scripts/lib/lighthouse-runs.mjs`, used by `scripts/lighthouse.mjs`; `docs/perf/web-vitals.md`; no D number applies). Switching to option 2 or 3 only changes how many runs the script asks for.
