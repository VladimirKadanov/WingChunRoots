# M11 — questions for the owner

M11 did not stop on any of these questions. Each one keeps its proposed default, marked in the code or the docs, until the owner answers it.

## 2026-11-01 — M11 — Where the committed GeoNames extract comes from

**Question:** the milestone's stop-and-ask condition about the GeoNames extract. `download.geonames.org` is not reachable from the cloud session, so the committed extract (`src/server/geo/data/geonames-places.tsv`, 5,210 places of BG, GR, DE, GB, US and HK above a population floor) was built by `scripts/geonames-extract.ts` from GeoNames `cities1000.txt` (dump of 2020-03-18) as redistributed unmodified in the npm package `cities-with-1000` 1.0.4, fetched with `npm pack`. That copy is CC BY 4.0 data like the official dump, but six years old, and its alternate names carry no language codes (Chinese and Cyrillic are told apart by script). Should the extract be regenerated from the official dump?

**Options:**
1. **Keep the committed extract for the pilot; the owner regenerates it from the official dump on his PC when convenient:** download `cities1000.zip` (or `allCountries.zip`) and `alternateNamesV2.zip` from <https://download.geonames.org/export/dump/>, then `pnpm geo:extract --cities cities1000.txt --alternate-names alternateNamesV2.txt --source "GeoNames cities1000.txt and alternateNamesV2.txt of <date>"`, commit the file and run `pnpm geo:load`.
2. Regenerate it in CI, where the official server is reachable, as a manual workflow that opens a PR with the new file.
3. Keep the npm-based extract permanently.

**Proposed default:** option 1 (`docs/adr/0013-schools-map.md` §1, `docs/schools-and-map.md` §2, `licenses/addenda/geonames.md`). The ids of places are derived from the GeoNames ids, so a regenerated extract keeps the cities that schools and profiles point to.

## 2026-11-01 — M11 — The answer for a school that is not public

**Question:** `/schools/<slug>` of a draft, a hidden school, a school whose pin needs a plan, or a mistyped address answers **200** with "This school is not listed" and `noindex, nofollow` (the API answers 404). Next.js 16 sends the status with the static shell before the page reads the school (ADR 0008), so a real 404 needs `src/proxy.ts`, which CLAUDE.md §13 limits to the two person paths. Should the school page get a real 404 too?

**Options:**
1. **Keep the 200 with `noindex, nofollow` and the same page for every case, as ADR 0008 variant 2.** Search engines treat it as a soft 404; nothing tells a missing school from a hidden one.
2. Extend the proxy's matcher to `/schools/:slug` with the same 500 ms check (CLAUDE.md §13 and ADR 0008 would change).

**Proposed default:** option 1 (`src/app/schools/[slug]/page.tsx`; `docs/adr/0013-schools-map.md` §10).

## 2026-11-01 — M11 — Edits of a listed school

**Question:** the M11 review (code-4) found that the listing review could be bypassed: an edit of an approved school went public at once with no review, and an edit made while a reviewer read a pending listing was approved unseen. The second gap is closed outright: a decision carries the version of the listing the reviewer saw (`review.decide` `schoolVersion`, the school's `updated_at`), and a listing changed since is refused with CONFLICT. For an edit of a school that is already listed, what should happen?

**Options:**
1. **The listing stays public with the edit, and an edit of what the school is, where, its website or its instructors (`name`, city, location mode, the exact pin, `websiteUrl`, instructors) opens a `school_listing` case again.** The reviewer approves the edit (the school stays listed) or returns the school to draft with a reason, which takes it off the map. Contacts, the description and the forms do not reopen the review. A second edit joins the open case.
2. The approved version stays public until the edit is approved (needs a pending copy of every reviewed field, a schema change and an editor that shows both versions).
3. No review of edits after the approval (the behaviour before the review), recorded as a default.

**Proposed default:** option 1 (`src/server/services/schools.ts`, `RE_REVIEWED_CHANGES` and `updateSchool`, `DEFAULT (no D number)`; `src/server/services/school-review.ts`). It closes the bypass without a schema change, and a declined edit takes the listing down at once. The owner may also want the description and contacts reviewed (they are public text), which would only add them to `RE_REVIEWED_CHANGES`.

**Answer:** (filled in by the owner)
