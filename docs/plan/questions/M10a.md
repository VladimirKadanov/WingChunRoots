# M10a — questions for the owner

M10a did not stop on any of these questions. Each one keeps its proposed default, marked in the code or the docs, until the owner answers it.

## 2026-11-01 — M10a — How long is evidence kept (GDPR)?

**Question:** the milestone's stop-and-ask condition. Evidence files (certificates, letters, photographs) are personal data of the student and often of other people in them. How long are they kept after a claim is decided, withdrawn or never sent, and what happens to them when the uploader's account is deleted?

**Options:**
1. **Keep every file until the owner decides; no automatic deletion.** `evidence_file.retention_until` stays empty; files are private and reachable only through the app (`/api/evidence/<id>`, 404 for everyone not allowed).
2. Keep the files of a verified claim as long as the link exists; delete the files of a refused or withdrawn claim N months after the decision (for example 6 or 12), and unattached files after 24 hours. A daily job (`retention.purge`, M01b) would set `retention_until` at the decision and delete the object and the row when it passes.
3. Delete all of an account's evidence when the account is deleted, whatever the state of its claims; a verified link then stays without its evidence.

**Proposed default:** option 1 (`docs/evidence-and-review.md`, `docs/adr/0012-evidence-and-review.md` §8, `docs/data-model.md` §7). Note: `evidence_file.uploaded_by_user_id`, `review_note.author_user_id` and `relationship_event.actor_user_id` reference `auth_user` with `ON DELETE RESTRICT`, so `pnpm account:delete` stops with `CONFLICT` for an account that uploaded evidence, wrote a review note or acted on a relationship. Options 2 and 3 need a rule for these rows too (delete, or keep them with the account reference anonymised), and a legal review.

## 2026-11-01 — M10a — Account deletion requests outside the review queue

**Question:** M07 said the deletion tool "comes with the review queue (M10a)". Should account deletion requests (`review_case.kind = 'deletion_request'`) appear in `/admin/review`?

**Options:**
1. **No: they stay on `/admin` (Account deletion requests) and are carried out with `pnpm account:delete`, as in M07.** The queue is open to moderators and archivists, and a deletion request names an account and its e-mail address, which only administrators see today.
2. Yes, for administrators only, with a button that runs the same deletion as the command.

**Proposed default:** option 1 (`src/server/services/review.ts`, `QUEUE_KINDS`; `docs/guides/admin-guide.bg.md` §13 and §15). Option 2 would also need the answer to question 1 above, because the deletion stops for an account with evidence.

## 2026-11-01 — M10a — The historical teacher form on its own route

**Question:** plan §5.6 places the historical teacher claim at `/dashboard/teachers/new?mode=historical`. Should it share that route?

**Options:**
1. **Its own route, `/dashboard/teachers/historical`, linked from Your teachers and from the lead of the request form; the request form refuses a historical or deceased teacher and names the other form.** `/dashboard/teachers/new` was at 169.4 kB of its 170 kB budget after M09; the evidence field and the claim form are a separate island, so the request form keeps its size.
2. The same route with `?mode=historical`, loading the claim form lazily: the route budget would have to be raised (only the owner may), or the claim form split so that the request form pays nothing for it.

**Proposed default:** option 1 (`src/app/dashboard/teachers/historical/`, `docs/adr/0012-evidence-and-review.md` §5).

## 2026-11-01 — M10a — Uploading evidence needs JavaScript

**Question:** every form since M02 works without JavaScript. The evidence field sends each file on its own, as the raw request body, so that the server refuses a file over 20 MB from its `Content-Length` before reading a byte. Should there be a no-JavaScript path?

**Options:**
1. **No: uploading needs JavaScript; the rest of the claim form works without it.** The guide says so. Phones, desktop browsers and mobile webviews all run JavaScript.
2. A `multipart/form-data` fallback on the same route: the server would have to read the multipart stream to find each file's size, so the 20 MB limit would be enforced while reading (still before storing), not before.

**Proposed default:** option 1 (`src/components/evidence/uploader.tsx`, `src/server/evidence-http.ts`, `docs/guides/user-guide.bg.md`, „Исторически учител и доказателства (M10a)“).
